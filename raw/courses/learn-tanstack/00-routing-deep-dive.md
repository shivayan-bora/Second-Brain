- `tsconfig.json`: [[TypeScript]] configuration.
- `eslint.config.js`: [[eslint]] configuration.
- `src`: Source Code of the application:
  - `router.tsx`: Exports the `getRouter()` function, a factory that calls `createRouter({ routeTree, scrollRestoration: true })`. TanStack Start calls it to build one router per request on the server and one in the browser. It doesn't define any routes itself.
  - `routeTree` comes from `./routeTree.gen`. That file is auto-generated by the TanStack Router plugin, which scans `src/routes/`.
  - `__root.tsx` becomes the root of that tree.
  - `index.tsx` becomes a child of the root, mounted at `/`.
  - Nothing imports `__root.tsx` or `index.tsx` directly. The generated tree wires them together by file name. `createFileRoute("/")` is also checked against that generated tree.
  - `route-a.tsx` and `route-b.tsx` are two routes corresponding to `/route-a` and `/route-b`.

```tsx
// router.tsx
import { createRouter } from "@tanstack/react-router";

// Import the generated route tree
import { routeTree } from "./routeTree.gen";

// Create a new router instance
export const getRouter = () => {
  const router = createRouter({
    routeTree,
    scrollRestoration: true,
  });

  return router;
};
```

## Static Pages

### How it Works?

#### File-Based Routing

- Each file inside the `routes/` folder represents one page of the application. The file's path and name determine the URL. This is called file-based routing.

#### Route File Structure

- Each route file uses `createFileRoute` from `@tanstack/react-router` to define the route. A component is passed as part of the route definition. The path is passed to `createFileRoute` as well, matching the file's location.
- This boilerplate is automatically generated when a new route file is created while the dev server is running.

#### Automatic Route Discovery

- While `npm run dev` is running, TanStack Start watches the `routes/` folder. Creating a new `.tsx` file automatically generates the route boilerplate inside that file and updates `routeTree.gen.tsx`.

#### `routeTree.gen.tsx`

- This file is automatically generated by TanStack Start and must be committed to version control. It provides type safety throughout the application. If it gets into a bad state, deleting it and rerunning `npm run dev` regenerates it.

## Static navigation

- To navigate from one page to another, we use the `Link` component. This creates a link that can be used to navigate to a new location.

```tsx
import { Link } from "@tanstack/react-router";

function Component() {
  return (
    <Link
      to="/somewhere/$somewhereId"
      params={{ somewhereId: "baz" }}
      search={(prev) => ({ ...prev, foo: "bar" })}
    >
      Click me
    </Link>
  );
}
```

- `Link` component accepts the following props:
  - `...props`:
    - Type: `LinkProps & React.RefAttributes<HTMLAnchorElement>`
- It returns an anchor element that can be used to navigate to a new location.

## Custom Links

- Imagine if we want to style `Link` components based on what page we're currently in i.e. active or inactive.
- To check if a `Link` matches or doesn't match the current URL, we use `activeProps` and `inactiveProps` respectively as follows:

```tsx
<Link
  to="/"
  activeProps={{
    className: "underline",
  }}
  inactiveProps={{
    className: "",
  }}
  className="hover:text-foreground text-muted-foreground"
>
  Home
</Link>
```

- We may have multiple `Link`s which needs to follow this practice. In that case, we can create a custom wrapper component on top of a `Link`:

```tsx
import type { LinkComponent } from "@tanstack/react-router";
import { Link } from "@tanstack/react-router";

export const CustomLink: LinkComponent<typeof Link> = (props) => {
  return (
    <Link
      activeProps={{
        className: "underline",
      }}
      className="text-muted-foreground hover:text-foreground"
      {...props}
    />
  );
};
```

- Apart from that, the generated anchor element has an `active` class and `data-status="active"` attribute when active allowing pure [[CSS]] targeting.
- We can also pass a function as children to the `Link` as follows:

```tsx
<Link to="/">
  {({ isActive }) => (
    <Button variant={isActive ? "default" : "outline"}>Home</Button>
  )}
</Link>
```

- For UI libraries like [[shadcn]], we can wrap a `Link` component with e.g. a `Button` and pass `asChild` to it. This gives the element the appearance of the button while retaining link behavior. Extra props like `className` can still be passed to reflect active state.

```tsx
<Button asChild variant="link" className="[&.active]:underline">
  <Link to="/">Home</Link>
</Button>
```

## Dynamic Navigation

- We can implement programmatic navigation using the `useNavigate` hook as follows:

```tsx
import { createFileRoute, useNavigate } from "@tanstack/react-router";
import { ContactForm } from "@/components/ContactForm";

export const Route = createFileRoute("/contact")({
  component: ContactComponent,
});

function ContactComponent() {
  const navigate = useNavigate();

  return (
    <ContactForm
      onSubmit={() =>
        navigate({
          to: "/",
        })
      }
    />
  );
}
```

> [!NOTE]
> Using `useNavigate` for navigation means the user loses browser-native link features:
>
> - Cannot command-click to open in a new tab.
> - Cannot right-click to copy the link address.
>
> Use `useNavigate` only when reacting to a JavaScript event. For regular navigation, prefer the `Link` component.

## Nested Routes and Layouts

- We can have nested routes using both flat file naming and folder-based structures.
- We use the `Outlet` component to render child routes.

### Flat Routes

- We can have nested routes using the dot (`.`) separator in the filename. e.g. `a.b.tsx` defines the route `/a/b`.
- We can also have `a.index.tsx` which corresponds to exact path match of `/a`

### Folder-Based Routes

- Alternatively, we can have a folder named after the parent route and place child route files inside it. e.g. a folder `c/` with a file `d.tsx` inside which defines the route `/c/d`.

### The `Outlet` Component

- The `Outlet` component is rendered inside a parent route component. It renders the matched child route in place of `<Outlet/>`.
  - `a.tsx` renders `Hello A` and an `<Outlet/>`. When visiting `/a/b`, the `Outlet` renders the content of `a.b.tsx`.
  - If a route has no child routes (a `leaf route`), the `<Outlet/>` can be omitted since nothing will be rendered inside it.

### Index Routes

- As mentioned above, an index route (e.g. `a.index.tsx`) matches the exact path of the parent segment (e.g. `/a`) without any additional segment.
- It is rendered inside the parent's `Outlet` when the URL exactly matches the parent path.

### Default Outlet Behaviour

- If no `component` is passed to `createFileRoute`, the default behaviour is to render an `Outlet`. This is useful when a route is only used as a wrapper and doesn't need it's own rendered output.
